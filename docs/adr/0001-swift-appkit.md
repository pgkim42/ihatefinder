# Swift와 AppKit으로 만들고, 삭제는 휴지통만 쓴다

IHateFinder는 맥 전용 파일 관리자이고, 실수가 나면 사용자 파일이 움직인다. Swift와 AppKit으로 만들고, 화면은 임시 폴더 테스트가 통과한 파일 연산만 호출한다. 삭제는 휴지통으로 보내는 동작만 둔다. 그 동작의 기준은 [behavior.md](../behavior.md)다.

AppKit의 상세 목록, 아이콘, 드래그를 앱과 같은 언어에서 호출하려고 Swift를 골랐다. 경로가 비는 경우를 컴파일러가 드러내게 하려는 이유다.

## 검토한 대안

- Objective-C는 같은 AppKit을 호출한다. 빈 값에 메시지를 보내면 조용히 지나가서, 파일 연산 실수가 늦게 나타난다.
- Rust는 복사 코어의 메모리를 지키기에 좋다. 테이블과 드래그는 AppKit 경계의 비안전 코드가 된다. 이 앱에서 깨지기 쉬운 곳이 그 경계다.

## 결과

디스크에서 바로 지우는 연산은 만들지 않는다. 화면을 붙이기 전에 임시 폴더에서 복사, 이동, 휴지통, 이름 충돌이 통과해야 한다. 다른 디스크로의 이동은 복사가 끝난 뒤에만 원본을 휴지통으로 보낸다.
